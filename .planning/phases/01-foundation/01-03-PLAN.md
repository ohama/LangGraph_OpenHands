  <name>Task 1: Pydantic models + REST routes + router wiring</name>
  <files>orchestrator/api/__init__.py, orchestrator/api/models.py, orchestrator/api/routes.py, orchestrator/main.py</files>
  <action>
Implement the API layer per RESEARCH.md Pattern 9 (shapes) and Pattern 6 (cancel), then wire the router into main.py.

1. `orchestrator/api/models.py` — Pydantic v2 models:
   - `GoalRequest(BaseModel)`: `goal: str` (add a min_length=1 constraint so empty goals 422).
   - `JobStatusResponse`: `job_id: str`, `status: str`.
   - `JobResultResponse`: `job_id: str`, `result: str | None`.

2. `orchestrator/api/routes.py` — `router = APIRouter()`:
   - `POST /goals` (status_code=202): generate `job_id = str(uuid.uuid4())`; **call `await store.create_job(job_id, goal)` BEFORE `await request.app.state.job_queue.put((job_id, goal))`** (RESEARCH.md Pitfall 2 — row must exist before the worker can pick it up). Return `{"job_id", "status": "PENDING"}`. Get the JobStore via the DATA_DIR jobs.db path (reuse the same path constant as main.py).
   - `GET /jobs/{job_id}/status`: get_job; 404 if missing; else return job_id + status.
   - `GET /jobs/{job_id}/result`: get_job; 404 if missing; 409 if status != "DONE"; else return job_id + result.
   - `DELETE /jobs/{job_id}` (status_code=200): get_job; 404 if missing; if terminal (DONE/FAILED/CANCELLED) return "already terminal"; else call `request_cancel(job_id)` — if it returns False (job queued, not running) call `store.set_status(job_id, "CANCELLED")` directly. Return status CANCELLED with the caveat string "checkpoint reflects last completed node, not mid-node state".
   - `GET /health`: open aiosqlite on jobs.db, `SELECT 1`; return 200 `{"status":"ok","sqlite":"reachable"}` on success, 503 on failure.
   - Import `request_cancel` from `orchestrator.worker.runner` lazily inside the DELETE handler (avoid import cycles at module load).

3. `orchestrator/main.py`: add `app.include_router(router)` at the TODO marker from 01-02. Ensure routes resolve the jobs.db path from the same DATA_DIR source.

Honor: status is read ONLY from jobs.db in handlers (never the checkpoint); POST writes the row before enqueue.
  </action>

  </verify>
